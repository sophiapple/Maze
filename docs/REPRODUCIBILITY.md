# Reproducibility

The repository separates **reconstructing a measurement**, **checking an implementation**, and **rerunning a model experiment**.
Each requires different inputs.

| Operation | Inputs in this repository | Command | What the output establishes |
|---|---|---|---|
| Saved-outcome reconstruction | 1,214 numeric question-by-arm records, reference aggregates, comparison definitions | `python scripts/reproduce_results.py --output runs/reproduced` | Exact reconstruction of included accuracies, counts, tokens, and paired statistics |
| Equation and implementation checks | Reference code, preserved compact code, deterministic test fixtures | `python -m unittest discover -s tests -v` | Numeric parity, shape contracts, policy behavior, and accounting invariants |
| Synthetic training/inference integration | Invented fixtures generated by the demo | `maze train-demo --output runs/train-demo` | Gradients, checkpoint export, and input-only inference work together |
| Archived scorer replay | Replay code included; corresponding real features and checkpoints supplied separately | `python reproduction/compact/replay.py --bundle PATH --output runs/scorer-replay.json` | Recomputed scores and decisions for a compatible supplied bundle |
| Fresh benchmark execution | Training/encoding/planning/collection/evaluation code included; data, model access, and fitted assets supplied by the user | See [USAGE.md](USAGE.md) | A newly measured result under the user's frozen configuration |

## Included measurements

The saved-outcome path reads already evaluated correctness indicators and recorded cost counters. The GPQA32 cohort additionally reconstructs 128 votes from opaque parsed-answer equivalence classes, preserving all 544 observations and 487 distinct cached request IDs.
It does not read answer text and therefore cannot independently re-parse or regrade the original responses. GPQA32 verifies voting from the recorded answer classes; the other cohorts verify the recorded aggregate outcomes.
It also does not train or load the original benchmark scorer.
This distinction is reflected in the generated JSON fields `fresh_generation: false` and `independent_regrading: false`.

The public scope is 21 named-control comparisons on three selected development cohorts, with nine positive comparisons highlighted.
All 99 GPQA questions are present in each of the ten GPQA99 arms; all 32 MMLU-Pro questions are present in each of its three included arms. All 32 GPQA32 questions appear in four arms. The GPQA cohorts share 13 original IDs; they are not independent replications.
The exporter selected complete arms, not successful questions within an arm.
Correctness zeros and measured invalid/truncated calls remain in the ledger.
The result code contains no performance-based row filtering or fallback to reported paper numbers.

Each comparison uses identical question membership within its cohort.
Accuracy, mean processed tokens, and ratios are computed with rational arithmetic before decimal display.
The source ledger is checked against its recorded digest, and all reconstructed arm statistics are checked against the frozen reference.

## Statistical interpretation

A paired bootstrap resamples question-level correctness differences, using 5,000 replicates and seed 20261020.
The 2.5th and 97.5th percentiles are interpolated deterministically.
These are descriptive intervals conditional on the included cohorts and configurations, not correction for development-time model selection.
Several comparisons share the same Maze predictions and must not be treated as independent replications.
No claim of universal improvement or statistical significance follows from the positive point differences alone.

## Fresh experiments

The included saved experiments cannot be regenerated end to end from this source archive alone.
The exact original feature tensors, trained checkpoints, benchmark-text cohorts, and response archives were not part of the supplied public assets.
To run a new experiment, prepare authorized data, freeze splits, encode inputs, collect training-only outcomes, fit the small scorer, and freeze an evaluation request plan before generation.
Keep the model revision, feature recipe, renderer, candidate proposals, seed, decoding limits, and evaluator in the run record.
Changing these settings creates a new experiment, not an exact replay of a table row.

## Verification

```bash
python scripts/reproduce_results.py --output runs/reproduced
python scripts/verify_release.py
python -m unittest discover -s tests -v
```

The checked-in [validation report](../validation/VALIDATION.json) records the environment and checks actually run when this package was assembled.
The included GitHub Actions workflow runs these checks after publication; it is not represented as a remote CI run that has already occurred.

## Paper transcription

`python scripts/reproduce_paper.py --output runs/paper` verifies all 15 included table excerpts against their SHA-256 bindings, re-extracts every table cell, and computes 60 main-table contrasts from 105 values using decimal arithmetic. Add `--paper /path/to/Maze-NIPS26-Oct20-v0/main.tex` to verify the full original source digest. This verifies author-reported table transcription; it establishes no independent empirical replication.

## What verification catches

`python scripts/verify_release.py` checks evidence digests, complete question/control coverage, parsed-class voting and cached-call accounting, exact saved reports, generated README highlights, and source integrity. Unit tests also exercise missing cohorts/controls, corrupted votes, shared-call inconsistency, source mismatch, and byte-identical report regeneration. The frozen outcomes are not filtered to make tests pass; tests verify the evidence contract, including adverse comparisons.

## Plot every control

```bash
python -m pip install -e '.[plot]'
python scripts/plot_results.py --output runs/development-results.svg
```

The chart shows all 17 arms, including controls that match or exceed Maze. It is generated from the same verified ledger as the tables. Its font rendering may vary by Matplotlib version; the numeric reports are byte-reproducible on the tested environment.

## Tested software environment

Version 0.2.1 local validation uses Python 3.12.7, NumPy 1.26.4, and PyTorch 2.2.2 on Intel macOS/CPU. The package constrains NumPy below 2 on Intel macOS for compatibility with its available PyTorch wheel. The CI matrix checks Python 3.11–3.13 core behavior and a separate Linux PyTorch job; its actual run status belongs to the PR checks. The prior 0.2.0 validation record is retained separately.
